# 2026-10-27 联调交接：跟随、语音动作与控制权

本版在二组 `v4.1-bluetooth-ai-integrated`（`9a7d2a17c4634b0c26bcab82a48410021031e714`）上继续集成。10 月 26 日进行了多轮实机测试，用户反馈跟随已有改善；发布前又用 Python 3.11.9 完成离线回归。没有把主观流畅度反馈写成量化性能提升。

**这次确实修改了二组 `drone_sdk/` 和四组 `modules/ai/` 的部分源码。** 原版仍在本仓库提交 `727f2af`；早期三组制动集成版为 `aeb9787`。已发压缩包和本机原版镜像保留。旧文档中“二四组未改动”的结论只适用于当时快照。

## 改进与边界

| 项目 | 本版行为 | 仍需关注 |
|---|---|---|
| 识别与启动 | 减少图像诊断和无关轮廓比较的开销；启动等待新鲜有效目标，失败后保留检测预览和原因 | 绿框只说明检测到目标，不表示已经进入跟随 |
| 跟随响应 | responsive_v1 响应参数；小偏移横移，大偏移逐渐分配给转向；启用上下跟随 | RC 是控制量，不是 cm/s；自动升降依赖新鲜高度遥测 |
| 减速与近距 | 保留接近趋势预测、提前减速；达到或进入参考距离时拦截继续前进；参考标记大小设上限 | 按标记大小估计相对距离，不是经标定的米制测距；不能替代避障 |
| 短暂漏检 | 漏检先归零；符合条件时用连续新观测恢复；目标丢失等待窗口保留为 30 秒 | 等待不表示按旧位置继续追赶；较长中断或异常需主动重新开始 |
| 跟随中移动 | 暂停跟随 → 执行六方向之一 → 等待动作后的新帧 → 更新对应轴基准 → 按条件恢复 | 无效目标、过期高度或动作失败时不盲目恢复；不擅自重复移动 |
| 悬停后继续 | 零速度请求成功后释放相应控制权，旧动作回调不能释放新会话；可重新发起跟随 | 悬停不自动重新跟随；要再次说“跟着我” |
| 语音接口 | 接通前后左右上下；兼容受限单接口简写；依据真实执行回执反馈 | 本地执行器只接受单条白名单调用，不执行任意模型代码 |
| 左右与旋转 | 本入口按用户面对机头的左右；默认转 90°，可指定整数 1–180° | 约定不会跟踪用户转身；最新左右转微调尚需现场确认 |
| HUD / 日志 | 显示目标、停止原因、RC 请求、高度时效和升降拦截原因；日志限制队列和分段体积 | 请求发出不等于飞机已完成位移 |

## 二组 SDK 修改清单

| 文件 | 修改目的 |
|---|---|
| `drone_sdk/_driver.py` | 复用同一 Tello 实例进行连接重试，避免旧实例析构破坏新连接状态；读取高度时间戳；补充下降高度检查 |
| `drone_sdk/telemetry.py`（新增） | 记录真实状态包的本机接收时间，向跟随提供高度时效；不是机载采集时间 |
| `drone_sdk/contract.py` | 给状态契约增加高度时间信息 |
| `drone_sdk/controller.py` | 为优先悬停增加成功后释放控制权的路径，使旧授权失效；失败时保留控制占用 |
| `drone_sdk/ai_bridge.py` | 六方向/旋转、跟随与动作交接、新帧基准调整、悬停释放控制、启动失败保留检测预览 |
| `drone_sdk/follow_integration.py` | 接通高度时效、启动目标等待及手动动作后的跟随恢复 |

没有反转底层 SDK 的左右或 yaw 坐标。二组后续若改这些接口，请一起跑交接测试。

## 四组语音 / AI 修改清单

| 文件 | 修改目的 |
|---|---|
| `modules/ai/program_runner.py` | 白名单六方向与旋转分派；兼容单条 takeoff() 等简写；角度/距离范围验证；传回真实状态 |
| `modules/ai/demo_text.py` | 六方向及旋转文本解析；按面对机头视角映射左右；默认 90°、显式角度保留；状态反馈 |
| `modules/ai/drone_adapter.py` | 补充对应动作适配和结构化执行回执 |
| `modules/ai/main.py` | 本地白名单工具说明、方向约定、动作结果语义、视频/状态入口与悬停后恢复说明 |
| `modules/ai/backends.py` | 对接修改后的 SDK 悬停与动作交接 |
| `modules/ai/gateway.py` | 成功悬停释放后清理对应授权，避免旧动作结束时干扰新跟随 |
| `modules/ai/volc_dialog.py` | 中断/悬停路径与控制释放语义衔接 |
| `modules/ai/follow_hud.py` | 展示检测、控制请求和高度保护状态 |

`turn_left()` / `turn_right()` 是本地语音白名单别名，不是新增的底层 SDK 公共方法。无参数默认 90°；旧 `rotate(带正负角度)` 仍接受，视角转换只在语音层做一次。旋转后保留悬停，不自动恢复跟随，以免跟随立即把机头转回；需用户再次发起。

三组主要改动位于 core.py、openpose_control.py、depth_brake.py、vision.py、service.py、config.py、session_log.py 及配置/HUD 适配文件，同步更新 SDK 校验哈希。新增接口、方向、启动、悬停、重连和响应方案回归测试。根目录 requirements.txt 补齐 soxr，避免耳机重采样时缺模块退出。

## 拉取后怎么运行

1. VS Code 打开完整仓库，按 README 创建 Python 3.11 的 .venv 并安装 requirements.txt。
2. 用 start_r3_voice.ps1 的 `-CheckOnly -RealDrone` 做离线检查，再用 `-ListDevices` 查本机耳机编号。
3. 飞机平放，桨叶/保护罩正确安装；电脑连接 TELLO Wi-Fi，另保留外网，退出手机控制和旧电脑控制进程。
4. 运行下列命令。编号 1 / 5 仅为示例；替换为本机实际耳机输入/输出。密钥在本机隐藏提示中输入。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start_r3_voice.ps1 -RealDrone -InputDevice 1 -OutputDevice 5
```

仓库内入口使用与当前现场脚本相同的 motion_follow 配置、面对机头方向约定、30% 起飞电量阈值和 120 cm 补高目标；已去掉个人电脑路径及固定耳机名字。新入口本身只完成离线校验，尚未重新做整轮硬件启动验收。原本机 start_voice_only.ps1 -RealDrone 保留，不需替换才能继续原机测试。

`-RealDrone` 已允许响应起飞指令，不要求额外解锁；启动不会自动起飞。`-NoAutoClimb` 关闭补高，`-ClimbTargetCm` 接受 80–160；120 cm 是目标而非精确高度保证。默认 `-DirectionFrame facing_pilot`；明确要改成飞机自身视角时才用 `-DirectionFrame aircraft`。

当前现场走的是未安装 Docker 时的本地白名单路径。有 Docker 时 main.py 会选沙箱执行器，指令能力和方向转换不能假定相同；**本次未给该路径做实飞验收**。完整模型程序执行与视觉问答应单独联调。

## 建议复测顺序

1. 地面先说“你好”“查看状态”，确认耳机语音、机载画面和电量；拿 ID0 标记确认检测状态。
2. 说“起飞”，稳定悬停后分别测试上/下、左/右各 20 cm；每次等真实动作完成再下一个指令。
3. 单独测试“向左转”“向右转”（默认 90°），再测“向左转 30 度”“向右转 45 度”；确认面对机头的方向与回执一致。
4. 重新对准标记并说“跟着我”。缓慢走开、停步、反向、小幅横向移动及抬高/降低标记，观察跟随响应和近距是否继续前冲。
5. 跟随中插入一次移动，确认没有刚移动就被跟随拉回；短暂遮挡标记再恢复，观察归零和重新识别。
6. 说“悬停”，稳定后再次说“跟着我”，确认无需落地重飞；最后说“降落”。

快捷键 Ctrl+Shift+Alt+A 请求零速度悬停，Ctrl+Shift+Alt+L 请求降落。先落地、停桨，再重启/切版本。没有避障能力，近距拦截也不保证物理停止距离。
