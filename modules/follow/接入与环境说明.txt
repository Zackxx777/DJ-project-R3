下午测试步骤 — 三组制动测试版（r3-4f58686-braking1）

这次要看三件事：能否跟上；人停下后是否靠近过头；换方向时是否来回冲退。不要只看绿框。

一、出发前
1. 完整解压这个包到一个新文件夹，保留旧包。电脑使用已有Python 3.11；原3.14不动。
2. 双击“离线自检.cmd”。看到校验通过再继续。若找不到Python3.11，使用已有3.11的python.exe：
   在命令窗口设置 set "R3_PYTHON=已有3.11环境的python.exe完整路径"，然后从该窗口运行自检或摄像头入口。
   不要临时切到3.14，也不用重新安装依赖。
3. 带对应编号的现有标记：A对应0，B对应1，C对应2。先测一架和一个目标。
   图案贴平在硬板上，黑框和白边完整；量黑色方块的实际边长（不包括白边），记下厘米数。
4. 带卷尺，用手机拍现场视频。准备记录标记介质、距离、光线、电量、版本和日志文件名；不必另写正式报告。

二、可选：出发前做电脑摄像头检查（仅模拟请求）
1. 关掉之前的测试窗口，避免两个程序抢摄像头。
2. 按标记编号双击摄像头测试_A_ID0.cmd、B_ID1或C_ID2。顶部应显示r3-4f58686-braking1。
3. 标记正对摄像头，在希望保持的位置固定；有绿框后点“1 记录参考大小”，再点“2 开始”。
4. 这次按下述动作手动测，不必点“3 分段测试”：原地5秒→缓慢拿远5秒→停住5秒→缓慢拿近5秒→停住5秒。
   看前后RC及“前后制动”一行；靠近时出现负数表示飞机后退请求。为提前制动，到参考大小之前也可能出现短暂负数。
5. 点“停止”，再关闭窗口。日志自动保存到 modules/follow/logs；保留本轮.jsonl和.bench.json。
   这轮只能确认识别到请求的过程，不能确认飞机是否真能刹住。

三、现场先确认用的是哪份代码
1. 二组继续使用他们的统一程序，只合并本包三组差异，不覆盖SDK或四组AI。保留现场已能运行的版本。
2. 启动前选择对应的R3_FOLLOW_CONFIG，停止旧进程后重启。配置检查可用：
   python -X utf8 -B modules/follow/check_follow_config.py --config modules/follow/configs/aircraft_A_ID0.json
   输出source_version=r3-4f58686-braking1、depth_brake_enabled=true、actual_depth_brake.profile=bounded_depth_lead_v1。
3. 正式运行后还要看该进程生成的日志：session_start.version应为r3-4f58686-braking1；motion_request里应有depth_brake。
   仅配置检查通过不代表统一程序加载了同一路径。若仍显示旧版本，先排查加载路径，不急着飞。
4. 三组负责拿标记、观察跟随和记时间。起飞、降落和独立接管按二组现场现有流程执行。
   场地允许的起始间距与停止线由现场操控人员确定，记具体米数；不要把模拟中的2米当作安全承诺。

四、第一轮：建立方向与停止基线
1. 在现场负责人完成起飞、稳定悬停后，标记正对机载摄像头，保持高度和距离不动。
2. 通过统一程序记录参考大小、启动跟随，记录参考间距。不要用电脑摄像头窗口代替真实跟随入口。
3. 小幅、缓慢远离，然后停住；预期出现前进请求，再随着接近而减小。实际机体表现也要拍到。
4. 缓慢靠近，再停住；预期能出现后退请求。方向以飞机看出去为准。
5. 通过现有入口停止跟随，确认请求归零，再观察机体还移动多久、多远。
   如方向相反、停止入口无效、持续逼近停止线或明显反复冲退，这轮立即交给现场操控人员接管，记录时间点后结束。

五、第二轮：主要对照，重复3次
每轮重新在同一条参考线校准，标记保持正对，尽量保持相同电量和光线条件。
1. 原地站定5秒。开始录像，说“本轮开始，版本制动测试版”。
2. 沿空旷直线缓慢远离约5秒，到地面事先标好的点。
3. 停住约5秒，清楚说“现在停住”。记录飞机最近到了哪里、前进请求何时减小、机体何时真正停住。
4. 在现场操控人员确认间距允许后，缓慢回到起始参考线，随后再停5秒。不要突然向飞机冲过去。
5. 停止跟随，记录本轮日志名。重复三次，动作距离尽量相同。
如需要与旧版现场比较，只在现场人员确认旧版可以继续测试的条件下，沿用相同线路和记录方式；没有旧版新实测就标明缺少现场对照。

六、主测试通过后，再做短补测
1. 小幅左右移动：应仍能转向对准；默认yaw模式本来就不横移，不能把横移0当故障。
2. 先站定，再遮挡标记约1秒后恢复：遮挡时请求应归零，恢复需重新确认目标；不应沿旧趋势继续冲。
3. 侧转再转正：看前后暂停原因是否清楚；恢复后是否突然跳出旧的制动请求。
4. 模型接管、人工停止和降落沿用统一入口；新跟随请求不能顶掉接管，也不能自动恢复被明确停止的任务。
只有主测试稳定后再考虑第二、第三架；不同ID只解决目标区分，不提供飞机之间的避碰。
